# Зоряна Тепла — персональний сайт ортодонта

Українськомовний сайт на React 19, TypeScript, Vite, Tailwind CSS 4, Motion та Lucide. Головна, чотири окремі сторінки послуг, політика конфіденційності й 404. Під час збірки сторінки перетворюються на статичний HTML: основний контент доступний пошуковикам і без JavaScript.

## Локальний запуск

Потрібен Node.js 22.12+ або 24 LTS та npm.

```sh
npm ci
npm run dev
```

```sh
npm run check
npm run build
npm run verify:static
npm run preview
npm test
```

`npm test` запускає Playwright на production-збірці та окремому dev-сервері з **тестовим** endpoint. Запити Formspree перехоплюються в браузері: реальні заявки не надсилаються. Тестам потрібен Chromium; у цій середовищі він є в `/usr/bin/chromium`. Для іншого шляху встановіть `CHROMIUM_PATH`.

## Де редагувати інформацію

- `src/data/site.ts` — підтверджені дані лікаря, асоціації, контакти, FAQ, справжні відгуки та результати.
- `src/data/services.ts` — описи, адреси та SEO-заголовки послуг.
- `src/Home.tsx` — редакційний контент головної.
- `src/Pages.tsx` — сторінки послуг і політика конфіденційності.
- `src/styles.css` — палітра, типографіка, анімації, адаптивні стилі.
- `.env.example` — публічні параметри збірки. Скопіюйте до `.env.local` для локальних налаштувань.

### Портрет та візуальні матеріали

Встановіть `site.doctor.portrait` у шлях до справжнього, дозволеного для публікації фото, наприклад `${import.meta.env.BASE_URL}images/zoryana-tepla.webp`. Без нього показується монограмна дизайн-заглушка, а не згенерована людина.

`public/images/editorial-still-life.webp` — оптимізоване AI-згенероване зображення предметів, використане як CSS-спрайт. Це ілюстрація тем послуг, **не фотографії лікаря або пацієнтів і не клінічні результати**. Зображення має розмір близько 104 КБ. Оригінальні логотипи асоціацій не використовуються.

Відгуки й клінічні фото за замовчуванням порожні. Додавайте лише справжні матеріали, для яких отримано згоду. Типи `Review` і `TreatmentResult` описані в конфігурації. Слайдери автоматично показують навігацію, коли додано кілька записів; порівняння працює мишею, дотиком та клавіатурою. Заглушки не містять вигаданих зубів «до/після», оцінок чи історій пацієнтів.

`public/images/social-card.png` — зображення Open Graph; його можна відтворити командою `node scripts/social-card.mjs` із SVG-джерела. Не використовується як портрет лікаря.

## Підключення онлайн-запису

Зараз **онлайн-надсилання не підключене**. На сайті є прямий запис телефоном. Заповнена форма без endpoint показує чесне повідомлення про недоступність і нічого не надсилає.

1. Створіть форму в [Formspree](https://formspree.io/), вкажіть і підтвердьте пошту одержувача.
2. Увімкніть захист від спаму та обмеження дозволених доменів у кабінеті Formspree. За потреби налаштуйте CAPTCHA на стороні сервісу; одного honeypot недостатньо проти всіх ботів.
3. Встановіть публічний `VITE_FORMSPREE_ENDPOINT=https://formspree.io/f/ВАШ_ID` у налаштуваннях збірки. Це адреса форми, не секретний API-ключ. Усі `VITE_*` значення потрапляють у клієнтський код — не додавайте туди секрети.
4. Перебудуйте сайт і зробіть контрольну заявку **з дозволу одержувача**. Перевірте приймання Formspree та отримання листа. До цього доставка реальної пошти не перевірена.

У формі є перевірка полів, honeypot, згода, блокування повторного натискання під час надсилання, таймаут і обробка серверних/мережевих помилок та 429. Успіх показується тільки після HTTP 2xx та JSON `{ "ok": true }`. При помилці введення зберігається лише в пам’яті поточної сторінки. Без JavaScript поля вимкнені — особисті дані не потраплять у URL через нативне GET-надсилання. localStorage, cookies та публічні файли для заявок не використовуються. Не збирайте через цю форму медичну інформацію.

Перед підключенням потрібно погодити обробку даних і строки зберігання з одержувачем, перевірити політику конфіденційності, доступи до Formspree та пошти. У тексті політики стан сервісу відображається автоматично.

## Статичний хостинг і SEO

### Публікація цього проєкту на GitHub Pages

Адреса для цього репозиторію: `https://formalandscape.github.io/dentist/`.
GitHub Pages уже налаштовано на **main → / (root)**. Команда `npm run prepare:pages` збирає та перевіряє сайт саме для цієї адреси, включно з canonical, sitemap і шляхами до ресурсів, та копіює публічну збірку з `dist/` у корінь репозиторію разом із `.nojekyll`.

Редагуйте вихідні компоненти в `src/`, HTML-шаблон — `src/index.html`, зображення — `public/`. Кореневі `index.html`, `404.html`, `.nojekyll`, `favicon.svg`, `robots.txt`, `sitemap.xml` та каталоги `assets/`, `images/`, `poslugy/`, `polityka-konfidentsiinosti/` — згенеровані файли публікації: не редагуйте їх вручну. Після змін виконайте `npm run prepare:pages`, зафіксуйте зміни вихідного коду й збірки та завантажте їх у `main`. GitHub публікує сайт автоматично. Раніше підготовлена гілка `gh-pages` збережена як окрема статична збірка, але поточним джерелом Pages є `main`.

Фактичний стан публікації видно у GitHub Actions → **pages build and deployment**. Успішне завантаження Git-коміту саме по собі ще не підтверджує завершення публікації.

`npm run build` лише створює папку `dist/`. `npm run prepare:pages` готує файли для вже налаштованого GitHub Pages; після завантаження цих файлів у `main` GitHub запускає публікацію.

Для власного домену використовуйте `VITE_BASE_PATH=/`, а `VITE_SITE_URL` має бути **реальним HTTPS origin без шляху**. Для GitHub Pages проєкту задайте `VITE_BASE_PATH=/dentist/` і origin вашого GitHub Pages у `VITE_SITE_URL`. Значення мають бути встановлені **під час збірки**. Не розміщуйте стару root-збірку в підкаталозі.

```sh
# Після встановлення реальних значень у .env.local:
npm run build
```

Збірка створює `index.html` для кожної адреси, `404.html` і `robots.txt`. З `VITE_SITE_URL` додатково створюються **валідна абсолютна sitemap.xml**, canonical та абсолютні Open Graph URL. Без реального домену вони навмисно не підміняються вигаданою адресою; збірка виводить попередження. Команда `build:pages` задає для цього проєкту origin `https://formalandscape.github.io` і шлях `/dentist/`. Власний домен можна налаштувати пізніше.

Google Search Console: додайте реальний сайт, використайте DNS-перевірку або `VITE_GOOGLE_SITE_VERIFICATION` для HTML-токена та перебудуйте сайт. Після публікації подайте `${VITE_SITE_URL}${VITE_BASE_PATH}sitemap.xml` через кабінет Search Console. Сам факт наявності метаданих не означає індексацію чи підтвердження Search Console.

Schema.org використовує тільки надані замовником відомості про лікаря та асоціації. Немає вигаданих адрес, рейтингів, дипломів або нагород. Перед публічним запуском підтвердьте актуальність професійних фактів.

Для майбутньої англійської версії тексти й дані розділені на окремі модулі. Зараз маршрути, повідомлення та `lang` — українські; перемикача на неіснуючий переклад немає.

## Перевірки

Playwright перевіряє переходи й статичний HTML послуг, FAQ, клавіатурне порівняння, справжні контактні посилання, валідацію форми, відсутність надсилання без endpoint, сценарії успіху/помилки/непідтвердженого приймання/429/збою мережі з mock-відповідями, honeypot, відсутність горизонтального переповнення на 320–1920 px, мобільне меню, reduced motion та роботу без JavaScript. Axe перевіряє доступність головної, мобільної форми, послуги та політики.

Це автоматизовані перевірки, а не підтвердження доставки реальних заявок, медичного змісту, індексації Google чи польових Core Web Vitals. Справжні LCP/INP/CLS слід оцінити після розміщення на цільовому хостингу й накопичення даних.
